# ADR-0002. Единый формат файла контекста для агента

Статус: **принято** (подтверждено Daniil 2026-07-27: канонический файл — AGENTS.md). Дата: 2026-07-27.

## Решение

В каждом репозитории должен быть один главный файл — **`AGENTS.md`, не длиннее 500 строк**.
Файл `CLAUDE.md` в этом же репозитории должен быть симлинком (ярлыком-указателем на другой файл) на `AGENTS.md`, а не отдельным файлом.

Обязательные разделы внутри AGENTS.md:
- зачем нужен этот репозиторий;
- команды сборки и тестов (например `make test`);
- карта модулей репозитория в упрощённом виде, по образцу того, что уже сделано в conversation_flow;
- ссылки на `openspec/specs/` и на контракты в store (store — это отдельный репозиторий, где лежат общие контрактные спеки; см. ADR-0001);
- правило «не трогать руками» для файлов, которые генерируются автоматически.

## Обоснование данными

Реальная ситуация хуже, чем звучало в постановке задачи.
Речь не про «три несовместимых стиля», а про то, что два репозитория вообще не имеют файла контекста.
У VA есть только `CLAUDE.local.md` на 24 строки.
У PCA нет вообще ничего (данные из таблицы в `OUR_PATTERNS.md`).

AGENTS.md выбран, потому что это уже сложившийся стандарт между разными агентными инструментами, а не изобретение с нуля.
Инструмент superpowers делает симлинк именно в эту сторону: `AGENTS.md → CLAUDE.md`.
В обзоре spec-compare тоже видно, что этот стандарт становится более принятым (`spec-compare/docs/comparison.md:78`).
Симлинк даёт совместимость с другими агентами — codex, cursor, cline — без дублирования одного и того же файла (это требование «агент-агностичность», один из важных пунктов задачи).

Лимит в 500 строк — не новое требование, оно уже было записано в `INIT.md:17`.
Текущие файлы укладываются в лимит: 147, 57 и 74 строки соответственно.
Значит задача не в том, чтобы что-то сокращать, а в том, чтобы дописать два недостающих файла.

## Путь миграции

1. В WBN: выполнить `git mv CLAUDE.md AGENTS.md && ln -s AGENTS.md CLAUDE.md`, затем дописать карту модулей.
2. В cybernet3.0: AGENTS.md уже является каноном, нужно только добавить симлинк CLAUDE.md.
3. В VA: написать AGENTS.md с нуля, взяв за основу `docs/MAP_VA.md`; файл `CLAUDE.local.md` остаётся личным файлом разработчика и не трогается.
4. В PCA: написать AGENTS.md с нуля.
5. В conversation_flow: переименовать CLAUDE.md в AGENTS.md и добавить симлинк; само содержимое не меняется, указатель на LIVING SPEC сохраняется.
6. Добавить проверку в `make test`: файл существует и не длиннее 500 строк (это одна строка кода в CI).

## Отклонено

Вариант «формат LIVING SPEC для всех репозиториев» отклонён.
LIVING SPEC в conversation_flow занимает 7504 строки — это не помещается в контекст агента и слишком дорого писать для остальных репозиториев.
Этот паттерн остаётся только в conversation_flow.

Вариант «CLAUDE.md — канон, AGENTS.md — симлинк» (в другую сторону) тоже рассмотрен и отклонён как основной, хотя технически рабочий.
Проблема: он ломает не-Claude агентов, которые ищут файл AGENTS.md первым.
В какую сторону делать симлинк — это в целом вопрос вкуса, важно только, чтобы канон был один.
Если Daniil в итоге предпочтёт CLAUDE.md как канон — это равнозначное решение, менять по сути нечего.
