# ADR-0014. Headroom выпилен из стека

Статус: **принято** (Daniil, 2026-07-31).
Дата: 2026-07-31.

## Контекст

Headroom стоял в CORE-наборе `setup-dev.sh` (default-yes) как MCP для сжатия
контекста с обещанием 60-95% экономии токенов. Наши собственные прогоны
(бенчмарк M1/M2, отчёт `docs/archive/benchmark-m1-m2/report-m1.md`) прямых
вызовов его инструментов не показали, а формулировка в README уже была
осторожной: "реальный выигрыш - место в контекстном окне, а не деньги".

Внешний бенчмарк (habr.com/ru/articles/1058780/, 3 прогона на конфиг в
изолированном контейнере, замеры по статистике самого Claude Code):

| Конфигурация | Стоимость (среднее) | Сжатие |
|---|---|---|
| Opus baseline | $0.392 | - |
| Opus + Headroom (token) | $0.635 (+62%) | ~2% |
| Opus + Headroom (cache) | $0.625 | 0% |
| Sonnet baseline | $0.450 | - |
| Sonnet + Headroom (token) | $0.652 (+45%) | ~2% |
| Sonnet + Headroom (aggressive) | $0.449 | 0% |

Диапазоны трёх прогонов не пересекаются: самый дорогой прогон без Headroom
дешевле самого дешёвого с ним. Ни один режим не выиграл у baseline; лучший
случай - сравнялся при 0% сжатия.

Механизм - уловка-22, видна в логах самой прокси
(`Pipeline: freezing first N/M messages`, `CCR: deferring tool injection ... to
preserve cache`): чтобы сжимать, нужно вставить retrieve-инструмент; вставка
инструмента меняет префикс запроса и ломает prompt-кэш; кэш-хит падает с ~98%
до ~94%, а промах дорожает в 10-12 раз ($0.5/M read против $5/M fresh input и
$6.25/M write). Поэтому прокси инструмент не вставляет - и, значит, ничего не
сжимает. Но даже с 0% сжатия само вклинивание прокси портит кэш и счёт растёт.

Локально `headroom perf` отчитывался о $569 "сэкономленных" из $981 - это
self-reported подсчёт по разнице "токенов до/после" без учёта экономики кэша,
то есть ровно та метрика, которую внешний бенчмарк опровергает.

## Решение

Headroom удалён из стека:

- `setup-dev.sh` - блок установки убран, секции перенумерованы (CORE теперь
  ponytail, rtk, graphify, ast-grep);
- `templates/sdd-doctor.sh` - убран из проверки `personal.*`, отсутствие
  Headroom больше не warning;
- README / README_RU / WORKFLOW.md / ONBOARDING.md / SDD_KIT_LAYERS.md -
  перенесён в "не предлагается" с этой причиной;
- у Daniil локально: user-scope MCP-запись удалена, бинарник и `~/.headroom`
  (51M state, ccr_store.db) снесены, процессы `headroom mcp serve` убиты;
- cc-bench: арма `headroom` и её smoke-проба удалены, `exercises: headroom`
  вычищено из проб `long`.

Экономия токенов в стеке остаётся за rtk (сжатие вывода shell), ponytail
(меньше кода) и graphify (граф вместо grep-and-read) - все три работают
до/вне запроса и prompt-кэш не трогают.

## Последствия

- Ставить Headroom обратно - только с воспроизводимым замером стоимости
  (не с его собственным отчётом о сжатии).
- Общее правило из этого случая: любой инструмент, который встаёт между
  агентом и API, оценивается по счёту, а не по "сжатым токенам"; ломать
  префикс prompt-кэша дороже, чем всё, что можно сжать.
- Исторические документы (`docs/archive/*`) не правим - там Headroom остаётся
  как след прошлых решений.
