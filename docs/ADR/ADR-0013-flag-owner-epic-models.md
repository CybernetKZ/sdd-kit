# ADR-0013. Владелец флага, эпик = YouTrack-задачи, модели через сабагентов, релиз-правило, payload профилей

Статус: **принято, часть «владелец флага» снята** (ADR-0026, 2026-08-04: флаги выпилены; эпик/модели/payload профилей в силе). Исходно grill-сессия №2 по WORKFLOW.md, Daniil, 2026-07-31.
Дата: 2026-07-31.

## Контекст

Второй гриль WORKFLOW.md на исполнимость: четыре шага процесса не имели
владельца или механизма - "кто включает флаг в prod", "как эпик проходит
QA-фазу и handoff", "как на практике plan/grill бегут на opus", "где
человек-QA догоняет бесфлаговые изменения". Плюс идея: профили могут нести
готовые файлы для известных репозиториев.

## Решения

### 1. Флагом владеет owner - весь жизненный цикл

Владелец флага включает флаг в prod после вердикта QA и он же удаляет флаг
(и мёртвую ветку кода) по `expires`. Одна роль на весь цикл, ничего нового
не вводим.

**Примечание 2026-07-31**: поля `owner` в коде больше нет - `feature_flags.py`
минимизирован до `имя -> expires` (ADR-0007, примечание о минимизации).
Владелец берётся из OpenSpec change, в котором флаг объявлен (и из `git blame`
строки реестра). Ответственность как процесс не меняется: владелец флипает
флаг в prod, владелец удаляет флаг по expires.

### 2. Эпик: 1 YouTrack-задача = 1 PR; QA один раз; handoff в конце

Единица работы фиксирована: 1 задача в YouTrack = 1 PR. Эпик режется на
задачи на intake - разбивка и прогресс живут в трекере, не в tasks.md.
Один OpenSpec change на весь эпик за одним флагом (ADR-0011). QA пишет
тесты ОДИН раз на весь change (все Scenarios, до первого PR);
нереализованные Scenarios - явные skip или за выключенным флагом.
Промежуточные мержи QA не дёргают; один `ready_to_test`, когда весь change
готов на stage. Исключение 1:1: фикс-PR уже принятой фичи едет по исходной
задаче.

### 3. Модели plan/grill - сабагенты с `model` frontmatter

Обещание "plan/grill на opus" получило механизм: агенты
`templates/agents/planner.md` и `plan-griller.md` (`model: opus`),
устанавливаются bootstrap'ом рядом с ревьюерами. planner пишет change
(по конвенциям /opsx:propose), plan-griller допрашивает план по ADR-0012
(практика grill-with-docs). Привязка моделей работает автоматом, не на
дисциплине.

### 4. Бесфлаговые изменения: `ready_to_test` держит релиз

Точка "человек-QA догоняет" для изменений без флага - релиз: перед деплоем
dev -> prod чеклист релиза проверяет в YouTrack, что ни один вошедший тикет
не висит в `ready_to_test` без вердикта QA. Это правило процесса (как
RAISE), не CI-гейт; автоматизация - если появится релиз-пайплайн.

### 5. Payload профилей: готовые файлы для известных репозиториев

`profiles/<repo-basename>/` (каталог рядом с `<repo-basename>.env`) может
нести заранее подготовленные файлы - заполненный AGENTS.md, конфиг
openspec и т.п. bootstrap копирует их с тем же правилом "никогда не
перезаписывать"; последующие generic-шаги пропускают то, что payload уже
дал.

## Последствия

- Новые файлы: templates/agents/planner.md, plan-griller.md; bootstrap
  ставит их, секция audit в sdd-doctor ожидает.
- Правки: WORKFLOW.md (узлы PLAN/GRILL/QA, секции Epics, QA availability,
  Status), README/README_RU, GLOSSARY (эпик, флаг, handoff).
- Payload-каталоги WBN и VA наполнены (2026-07-31): снапшоты выверенных
  AGENTS.md обоих репозиториев лежат в `profiles/web-backend-new/` и
  `profiles/voice-agent-constructor-backend/`; при изменении AGENTS.md в
  репозитории обновлять и снапшот в ките.
