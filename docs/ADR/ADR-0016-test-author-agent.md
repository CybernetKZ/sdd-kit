# ADR-0016. Тесты до кода пишет агент `test-author`; владение QA - целевое состояние

Статус: **принято** (гриль-сессия №3, Daniil, 2026-08-01).
Дата: 2026-08-01.

## Контекст

WORKFLOW.md, feature-flow шаг 3, README и QA-SDD-PROCESS.md утверждают в
настоящем времени: "QA пишет тесты по спек-дельте, разработчики тесты не
пишут". Фактически человека-QA в этой роли сейчас нет: секция Status сама
помечает QA-SDD-PROCESS как **planned**, а ADR-0012 п.5 описывает обход
("QA недоступен - dev запускает независимого QA-агента") как исключение.

Исключение стало нормой. Каждая задача идёт по fallback-ветке, и при этом
запуск "независимого QA-агента" ничем не задан: нет файла агента, нет модели,
нет списка инструментов, нет запрета трогать код реализации. То есть самый
важный инвариант процесса - тесты написаны ДО кода и не автором кода - держится
на памяти разработчика.

## Решение

### 1. Тесты по спек-дельте пишет выделенный агент `test-author`

Новый агент кита: `templates/agents/test-author.md`, ставится bootstrap'ом в
`.claude/agents/` рядом с `planner` / `plan-griller` / ревьюерами.

Вход - активный change: `openspec/changes/<id>/specs/`. На каждый
`#### Scenario:` - ровно один pytest-тест (или скелет с `pytest.mark.skip` и
причиной, если сценарий упирается в окружение), с трейсер-комментарием
`# spec: <requirement-id> / <scenario>`. Структура AAA. Агент обязан **прогнать
тесты и показать RED** - падение по задуманной причине, а не ImportError по
пути.

Жёсткие запреты в самом агенте: не править нетестовые файлы, не писать
реализацию, не ослаблять ассерты ради зелёного. У агента нет доступа к правке
кода как политики - тулы `Write`/`Edit` есть (иначе он не создаст тестовый
файл), но правило "только тестовые файлы" записано в его инструкции и
проверяется на ревью diff'а.

Отдельная защита от подгонки: **если тест неожиданно проходит - это сигнал, что
поведение уже реализовано**. Агент обязан об этом доложить, а не изобретать
искусственное падение.

### 2. Владение QA - целевое состояние, не текущее

Человек-QA как владелец тестов остаётся целью процесса и не отменяется.
Меняется только формулировка времени: сегодня тесты пишет агент, человек-QA
валидирует - до включения флага в prod, а для бесфлаговых изменений до релиза
(правило `ready_to_test` держит релиз, ADR-0013).

Это заменяет абсолютное утверждение "QA пишет тесты, разработчики тесты не
пишут" в WORKFLOW.md шаг 3 и в feature-flow. Что остаётся неизменным и не
обсуждается:

- тесты существуют и красные ДО первой строки реализации;
- автор реализации тест не пишет и не правит; спорный тест оспаривается через
  Scenario (ADR-0012 п.2), а не редактируется;
- адверсариал-чек (независимый агент ищет green-stub) остаётся обязательным;
- в PR помечается, что тесты сгенерированы агентом без валидации человеком-QA.

### 3. Адверсариал-чек не сливается в test-author

Проверяющий и пишущий - разные запуски. Агент, который сам себя проверил на
green-stub, проверку не прошёл. Адверсариал-чек остаётся отдельным шагом в
другом контексте (QA-SDD-PROCESS.md).

## Отклонено

- **Оставить "QA пишет тесты" как есть** - отклонено: доки описывали бы роль,
  которую сегодня никто не исполняет, а реальный путь (агент) остался бы
  незаданным.
- **Разрешить разработчику писать тесты, раз QA нет** - отклонено: автор кода,
  пишущий тест на свой код, воспроизводит своё же непонимание сценария; весь
  смысл tests-before-code в независимости источника.
- **Один агент пишет тесты и он же адверсариально их проверяет** - отклонено,
  см. п.3.
- **`test-author` без права `Write`** - отклонено: тогда тестовые файлы
  создаёт кто-то другой, и инвариант "не автор кода" снова держится на памяти.

## Последствия

- Новый файл `templates/agents/test-author.md`; агент вписан в `install.sh`,
  `uninstall.sh`, feature-flow шаг 3, incident-flow (регресс-тест),
  WORKFLOW.md (шаг 3 + Status), README/README_RU (таблица агентов), глоссарий.
- QA-SDD-PROCESS.md остаётся каноном фазы 3 по содержанию (что валидируется,
  что такое traceability, как выглядит адверсариал-чек); меняется только
  исполнитель шага "написать тест".
- Переход к человеку-QA не потребует правок кита: меняется одна строка в
  feature-flow шаг 3 (кто запускает), агент остаётся как fallback.
- Traceability-гейт (каждый Scenario ⇄ один тест) остаётся planned; пока его
  нет, трейсер-комментарий `# spec: ...` - единственный след, и он же будущий
  вход для гейта. Формат комментария фиксируется этим ADR, чтобы гейт потом
  писался по существующим тестам, а не наоборот.

## Связано
