# ADR-0012. Уточнения WORKFLOW: термины, спорный тест, QA-fallback, эпик, статус

Статус: **принято** (grill-сессия по WORKFLOW.md + README.md, Daniil, 2026-07-31).
Один пункт помечен как временное решение - см. п. 6.
Дата: 2026-07-31.

## Контекст

Гриль WORKFLOW.md и README.md на "кристальную ясность" нашёл дыры, в которые
упирается свежий читатель: термин "manifest" не определён нигде; из красного
теста QA нет выхода, если тест ошибочен; выбор тира опирался на неопределённое
"ticket value"; QA стоит на критическом пути каждой задачи без fallback'а;
критерия эпика нет; документ не отличает работающее от запланированного.

## Решения

### 1. Слово "manifest" не используем

"Manifest" везде заменён на "spec delta" (спек-дельта): Requirements +
Scenarios внутри change'а - то, что QA валидирует и из чего пишет тесты.
Один термин вместо двух; глоссарий дополнен.

### 2. Спорный тест: dev оспаривает, не правит

Красный тест - три случая с тремя выходами: (а) код неверен - чинить код;
(б) тест противоречит своему Scenario - dev возвращает тест QA с аргументом
"противоречит Scenario X", арбитр - текст Scenario, dev тест не правит
никогда; (в) неясен сам Scenario - спек-дельта назад автору (уже
существовавший путь). Путь (б) добавлен в диаграмму.

### 3. Тир по эвристике, не по "ticket value"

Таблица в WORKFLOW: опечатка/конфиг/изолированный баг без кросс-сервисного
влияния - light; обычная фича в одном сервисе - standard; кросс-сервис /
миграция данных / новая архитектура / неизвестная территория - deep.
Dev может переопределить; тир + почему - в change.

### 4. Гриль: агент допрашивает, dev отвечает

Гриль плана (standard/deep) ведёт агент на opus/fable (практика
grill-with-docs); разработчик отвечает; безответное - вопрос автору тикета.

### 5. QA недоступен: независимый QA-агент, не dev

QA - роль на критическом пути фазы 3. При недоступности человека-QA dev
НЕ пишет тесты в своей сессии: он запускает независимого QA-агента
(по QA-SDD-PROCESS.md) в отдельном контексте; адверсариал-чек обязателен;
в PR - пометка "тесты сгенерированы без валидации человеком-QA".
Человек-QA догоняет до включения флага в prod.

### 6. Тупик misuse/infra: коммент + статус (ВРЕМЕННОЕ решение)

Root-cause док уходит комментарием в тикет (суть + ссылка), статус меняется
через youtrack-mcp; закрывает тикет автор/процесс-оунер, не dev. Помечено
как временное - конкретный статус и владелец закрытия требуют обсуждения
с командой.

### 7. Эпик: помечен в тикете + подозрение по числам гейтов

Эпик объявляется в тикете на intake. Независимо от тикета: план предсказывает
>1500 строк или >2 дней на один PR (числа ADR-0006) - подозревать эпик и
уточнить у автора до старта.

### 8. План vs факт: секция Status + маркеры (planned)

WORKFLOW описывает целевой процесс; секция Status в конце (с датой проверки)
перечисляет, что уже живёт, а что запланировано; ещё не существующие гейты
(make test, traceability gate, QA quality gate) помечены "(planned)" прямо
в тексте/диаграмме.

### 9. Документация: карта чтения; README_RU остаётся

README.md открывается картой чтения (новичок - ONBOARDING.md; процесс -
WORKFLOW.md; установка - README.md). README_RU.md сохраняется и
поддерживается; наверху - дисклеймер "источник истины - README.md" с датой
перевода. Диаграмма WORKFLOW разрезана на две: поток и карта тул-фаза.
