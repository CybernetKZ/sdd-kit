# ADR-0007. Feature-флаги: свой минимальный реестр со сроком жизни, без платформ

Статус: **принято** (решения подтверждены Daniil 2026-07-30 в grill-сессии). Дата: 2026-07-30.

## Решение

Флаг - это переключатель в конфигурации, который позволяет влить код до того, как он включён для всех.
Нужен в двух случаях: работа не помещается в 2-дневную ветку (ADR-0006) и миграция контрактов.

**Реализация - один модуль на репозиторий, без внешних сервисов:**

1. Шаблон `feature_flags.py` в sdd-kit: класс `Flags` на pydantic-settings
   плюс реестр метаданных `owner / ticket / expires` (дата смерти флага).
   Доступ к флагу - через функцию `is_enabled("имя")`, а не чтение настроек по месту.
   Так при необходимости можно перейти на OpenFeature без правки мест вызова.
2. `make sdd-flags` входит в `sdd-check`.
   Просроченный флаг: 7 дней после `expires` - предупреждение в CI, дальше - красная проверка.
   Продление `expires` видно в diff и обсуждается на ревью.
3. **Кросс-репо флаги** (продюсер и консюмер в разных репозиториях, например redis-стримы):
   источник правды - спека контракта в центральном store (cybernet-specs).
   Дата `expires` живёт только в спеке; `feature_flags.py` каждого репо держит ссылку `spec:`
   без собственной даты, `make sdd-flags` читает дату из зарегистрированного store.
   Store не зарегистрирован - предупреждение, не блок.
4. Объявление флага и его `expires` - часть OpenSpec change.
   "Удалить флаг" - задача в том же tasks.md.
5. Рецепт миграции контрактов - секция в skill `feature-flow` (не отдельный skill):
   трогаешь фиксированный контракт -> обязательный план expand/contract + флаг в спеке.
   Для крупных замен (HubTalk, отказ от Asterisk) - branch by abstraction:
   прослойка над старым поставщиком, конфиг-флаг выбирает реализацию, потом прослойка удаляется.

## Отклонённые варианты

- **Unleash / Flagsmith / OpenFeature-платформа** - отклонено: дают таргетинг по пользователям
  и процентную раскатку, которых нет в требованиях, а стоят отдельный сервис и SDK в каждом репо.
  Путь миграции при необходимости: openfeature-sdk + flagd, места вызова не меняются.
- **FAIL сразу при просрочке** - смягчено до "7 дней WARN, потом FAIL":
  просроченный флаг блокирует все PR репозитория, невиновным нужна неделя на реакцию.
- **Своя дата expires в каждом репо** - отклонено: даты разъедутся,
  и рассинхрон контрактов, ради которого всё затевалось, вернётся.
- **Общий флаг через helm/env двух сервисов** - отклонено: непонятен владелец,
  появляется зависимость деплоев.
