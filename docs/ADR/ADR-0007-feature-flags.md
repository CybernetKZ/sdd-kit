# ADR-0007. Feature-флаги: свой минимальный реестр со сроком жизни, без платформ

Статус: **принято** (решения подтверждены Daniil 2026-07-30 в grill-сессии). Дата: 2026-07-30.

## Решение

Флаг - это переключатель в конфигурации, который позволяет влить код до того, как он включён для всех.
Нужен в двух случаях: работа не помещается в 2-дневную ветку (ADR-0006) и миграция контрактов.

**Реализация - один модуль на репозиторий, без внешних сервисов:**

1. Шаблон `feature_flags.py` в sdd-kit (stdlib, ~25 строк, ставится bootstrap'ом):
   реестр `FLAGS: dict[str, str]` — имя флага → дата смерти (`expires`, ISO).
   Включение — переменная окружения `FLAG_<NAME>=1`; по умолчанию флаг выключен везде.
   Доступ к флагу - через функцию `is_enabled("имя")`, а не чтение env по месту
   (незарегистрированное имя → `KeyError`).
   Так при необходимости можно перейти на OpenFeature без правки мест вызова.
2. `make sdd-flags` входит в `sdd-check`.
   Просроченный флаг: 7 дней после `expires` - предупреждение в CI, дальше - красная проверка.
   Продление `expires` видно в diff и обсуждается на ревью.
3. **Кросс-репо флаги** (продюсер и консюмер в разных репозиториях, например redis-стримы):
   одинаковая дата `expires` руками в обоих репо плюс строка в спеке контракта
   (центральный store, cybernet-specs). Расхождение дат ловится на ревью change,
   не сканером.
4. Объявление флага и его `expires` - часть OpenSpec change.
   "Удалить флаг" - задача в том же tasks.md.
5. Рецепт миграции контрактов - секция в skill `feature-flow` (не отдельный skill):
   трогаешь фиксированный контракт -> обязательный план expand/contract + флаг в спеке.
   Для крупных замен (HubTalk, отказ от Asterisk) - branch by abstraction:
   прослойка над старым поставщиком, конфиг-флаг выбирает реализацию, потом прослойка удаляется.

## Отклонённые варианты

- **Unleash / Flagsmith / OpenFeature-платформа** - отклонено: дают таргетинг по пользователям
  и процентную раскатку, которых нет в требованиях, а стоят отдельный сервис и SDK в каждом репо.
  Путь миграции при необходимости: openfeature-sdk + flagd, места вызова не меняются.
- **FAIL сразу при просрочке** - смягчено до "7 дней WARN, потом FAIL":
  просроченный флаг блокирует все PR репозитория, невиновным нужна неделя на реакцию.
- **Своя дата expires в каждом репо** - отклонено в 2026-07-30 (даты разъедутся);
  ревизия 2026-07-31 (см. примечание) - дата всё же дублируется руками,
  но синхронность проверяет ревью change, а не код.
- **Общий флаг через helm/env двух сервисов** - отклонено: непонятен владелец,
  появляется зависимость деплоев.

## Примечание 2026-08-01 (флаг - инструмент по требованию)

Реализация и lifecycle не меняются ни на строку; меняется статус флага в
процессе. Первое предложение раздела «Решение» («нужен в двух случаях: работа
не помещается в 2-дневную ветку и миграция контрактов») перестало быть верным
в первой половине: гейт возраста ветки advisory, обязательного клапана он не
требует (ADR-0015). Флаг берут по требованию - миграция фиксированного
контракта, branch by abstraction, эпик, чей полуготовый вид не должен быть
доступен в prod. Ни один шаг feature-flow не обязывает завести флаг.
Открытый вопрос там же: где физически ставится `FLAG_X=1` на stage/prod.

## Примечание 2026-07-31 (минимизация)

Реализация урезана с 112 до ~25 строк (аудит `docs/SDD_KIT_LAYERS.md`, слой 5):

- «pydantic-settings» из п.1 никогда не существовало в коде - всегда был plain `os.environ`;
  формулировка исправлена по факту;
- удалены `FlagMeta`, поля `owner` и `ticket` (потреблялись только print'ом; живут в OpenSpec
  change и `git blame`) и `spec=` + `_store_expires()` (regex-rglob по чужому репо под сценарий,
  который ни разу не случился, с WARN-фолбэком, делавшим гейт декоративным);
- значение словаря `FLAGS` теперь и есть дата `expires`, поэтому «флаг без expires» невозможен;
  `check()` валит нераспарсиваемую дату и просрочку > `GRACE_DAYS`;
- `feature_flags.py` добавлен в `bootstrap.sh` - гейт `make sdd-flags` перестал быть
  всегда-зелёным в свежем репо.

**Канон lifecycle флага - docstring `templates/feature_flags.py` + этот ADR.** Остальные доки
ссылаются, а не пересказывают.
