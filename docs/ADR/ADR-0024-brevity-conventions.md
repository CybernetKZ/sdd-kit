# ADR-0024: Краткость текстов — оркестрация в скилле, знания в references

Статус: **принято**. Дата: 2026-08-04. Контекст: ревизия текстов ADR-0022
оставила скиллы самодостаточными и длинными (feature-flow 252 строки, tz 350);
образец компоновки — mattpocock/skills, где workflow-скилл занимает один экран
и делегирует остальное.

## Решения

1. **SKILL.md workflow-скилла = оркестрация, цель ≤60 строк** (жёсткий
   потолок прежний — 500): фазы, кто исполняет (агент/скилл), гейты, стопы.
   Всё остальное — не в SKILL.md.
2. **Знания уезжают по типу**:
   - справочный материал процесса (жизненный цикл флага, механика эпиков,
     таблицы гейтов) → `references/*.md` рядом со скиллом, с явным указанием
     когда читать (progressive disclosure);
   - доменные правила репозитория (инварианты платформы, DoD-добавки) →
     `AGENTS.md` репозитория; скилл ссылается, не пересказывает.
3. **Таблица «тир → конвейер → модели» (§1b) остаётся в SKILL.md
   feature-flow** — это оркестрация, и на неё указывают `/tz`/`/tz-implement`.
4. **Агент-промпты остаются самодостаточными**: агент загружается целиком при
   спавне, вынос чеклиста в отдельный файл добавляет tool-call каждому запуску.
   Режется проза, чеклисты и правила остаются.
5. **tz-трилогия**: «зашитые принципы платформы» (шаг 4 `/tz`) переезжают в
   AGENTS.md conversation_flow (половина там уже есть — слить, не дублировать);
   миграционная механика (нумерация из 4 источников, main-drift) не трогается —
   она умирает на cutover сама.
6. **Вендоренные скиллы** (grilling, domain-modeling из mattpocock/skills)
   не редактируются; house-rules живут в обёртках grill-me/grill-with-docs.
7. Приоритет ADR-0022 сохраняется: правильность > эффективность > дедупликация
   > краткость. Резать нельзя то, что агент без этого делает неверно.
