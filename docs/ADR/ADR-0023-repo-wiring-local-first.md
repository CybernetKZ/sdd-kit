# ADR-0023. Подключение репозиториев: store фикс-путём, граф в git, CI выпилен (local-first)

Статус: **принято** (grill-сессия по подключению репозиториев, Daniil, 2026-08-04).
Дата: 2026-08-04.

## Контекст

Целевой репозиторий сейчас один — conversation_flow (остальные пять помечены
как вероятно deprecated и пропускаются). Проверка CF показала: AGENTS.md сломан
(9 байт, текст «AGENTS.md» — неудавшийся симлинк; sdd-check это не ловит),
graphify-индекса нет (intake WEB-2316 шёл без графа), промпты в `.claude/` —
доревизионные (ADR-0022 туда не доехал), легаси-скиллы patch-* живут рядом с
заместившим их tz-процессом. Store подключён соседним клоном и работает, но
шаг установки нигде не автоматизирован. CI-гейты (sdd-gate, tbd-gates,
autoreview) — advisory по ADR-0015, при одном разработчике не читаются никем
и усложняют картину.

Ограничение, выясненное из stores-beta гайда OpenSpec: реестр store —
**машинный** (`openspec store register <path>`: id → один путь на машину),
поэтому store-сабмодуль в каждом репо даёт несколько чекаутов одного id, из
которых читается только зарегистрированный. «No sync, ever» — свежесть store
это ручной `git pull` by design.

## Решения

1. **Store — гибрид «клон в фикс-пути через install.sh».**
   `install.sh --machine-only` сам клонирует `CybernetKZ/cybernet-specs` в
   стандартный путь (`~/cybernet/cybernet-specs`; уже существующий клон —
   переиспользуется) и регистрирует его (`openspec store register`). Не
   сабмодуль и не копия-подпапка: машинный реестр допускает один путь на id,
   копии молча разъезжаются. Репозиторию остаётся только `references:` в
   `openspec/config.yaml`. sdd-doctor получает проверку: store зарегистрирован,
   путь существует, давность последнего `git pull` — предупреждение.

2. **AGENTS.md для CF: восстановить + актуализировать.** Содержимое — из
   git-истории CF (коммит 9583b791), сверить с новым шаблоном кита (разделы
   «Specs and contracts» со store-цепочкой, «Codebase search») и дополнить.
   В `make sdd-check` — гард от пустого/битого файла (минимальное содержимое,
   а не только «файл есть и ≤500 строк»).

3. **Graphify-граф коммитится в git.** `graphify-out/graph.json` — командный
   артефакт: дорогой первый билд (LLM-ключ или интерактивный `/graphify`)
   делается один раз на команду, обновление — `make sdd-index` (AST, без
   ключа) перед большим intake, коммитится вместе с работой. sdd-doctor
   проверяет: граф существует, не старше N дней от HEAD (предупреждение).
   ADR-0004 не меняется: граф — навигация/контекст, не гейт.

4. **След графа в плане.** planner пишет в proposal.md строку
   `Graph probes: <символы>` (или `graph absent: <почему>`); plan-griller и
   ревьюеры видят, пользовались ли графом. Это провенанс (честность вместо
   церемонии, как у гриля), НЕ жёсткий гейт — жёсткий противоречил бы ADR-0004.

5. **CI выпилен целиком, локальное остаётся.** `sdd-ci.yml` и `autoreview.yml`
   уходят из install.sh и templates в `docs/archive/` кита; из CF удаляются
   `.github/workflows/sdd-ci.yml` и `autoreview.yml`. Остаётся всё локальное:
   pre-commit хуки, spec-guard, блокер `--no-verify`, `make sdd-check` /
   `sdd-test` / `sdd-review` / `sdd-flags`. TBD-дисциплины (возраст ветки,
   размер PR — ADR-0006) становятся процесс-правилами без автоматики.
   Это уточняет ADR-0015: не «advisory по выбору», а «серверных гейтов нет,
   единственные гейты — локальные». Возврат CI — отдельное решение, шаблоны
   лежат в архиве.

6. **Конвергенция CF с китом.** `install.sh --repo-only` перезапускается на
   CF (свежие промпты ревизии ADR-0022 — это и есть её dry-run). Легаси-скиллы
   `patch`, `patch-implement`, `patch-review` удаляются (замещены
   tz-процессом); `tz`, `tz-implement`, `tz-review` живут до конца миграции
   (фаза 5, PLAN_CF_MIGRATION). Миграционный слой (LIVING SPEC параллельно,
   spec-guard OFF по `.spec-guard-paths`, tz-нумерация) — не трогается, он
   идёт по плану ADR-0019. Ответ на вопрос «почему в CF другой workflow»:
   это (а) осознанный миграционный слой, (б) устаревшая установка, (в) ещё
   не удалённое легаси — (б) и (в) закрывает этот ADR, (а) закроет фаза 5.

## Последствия

- install.sh: +клонирование/регистрация store, −копирование CI-файлов;
  sdd-doctor: +store-проверка, +graph-проверка, +AGENTS.md-гард.
- Тексты, упоминающие CI (WORKFLOW.md диаграмма/статус, feature-flow §7,
  Makefile.sdd комментарии), правятся под «серверных гейтов нет».
- planner.md получает строку Graph probes; plan-griller — указание её читать.
- Один недостаток фикс-пути: путь машинный, а не проектный — двум наборам
  репозиториев с разными версиями store на одной машине станет тесно;
  приемлемо, пока store один.
