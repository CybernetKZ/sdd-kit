# ADR-0022. Конвенции текстов промптов (skills/agents/prompts кита)

Статус: **принято** (grill-сессия по ревизии текстов, Daniil, 2026-08-04).
Дата: 2026-08-04.

## Контекст

Тексты кита (WORKFLOW.md, templates/agents/*, templates/skills/*, review-prompt,
CI-конфиги, tools/cf/*) выросли инкрементально, по одному ADR за раз. Накопилось:

1. **Дрейф против реальности**: таблица «Where the named pieces live» в
   WORKFLOW.md не знает про `executor` (появился в ADR-0021); статусы и
   формулировки местами отстают от шипнутого.
2. **Двойной источник правды**: тиры, эпики, disputed tests описаны и в
   WORKFLOW.md, и в feature-flow — при каждом изменении правится два текста,
   и один из них неизбежно отстаёт.
3. **ADR-теги внутри промптов**: feature-flow несёт ~30 упоминаний `ADR-XXXX`.
   Агенту ссылка не нужна (ADR в целевом репо отсутствуют по определению),
   человеку нужна — но не в контексте агента.
4. **Смешение языков** без зафиксированного правила: agents/skills английские,
   repo-auditor и tools/cf/* русские.
5. **~60 строк дословных дублей** между backend-reviewer и database-reviewer
   (Review discipline, Spec Compliance, Tool-assisted checks, Output format)
   без пометки, что это осознанно.

## Решение

1. **Приоритет целей ревизии** (при конфликте выигрывает верхняя):
   правильность (текст соответствует тому, что реально шипнуто) →
   эффективность промпта (агент реально следует) → дедупликация →
   экономия токенов. Короткий, но неверный текст хуже длинного верного.

2. **ADR-теги не живут в промптах.** В тексте skill/agent остаётся само
   правило одной фразой, без `ADR-XXXX`. Соответствие «правило → ADR» живёт
   в одном месте — grounding-таблице WORKFLOW.md (раздел «Where the named
   pieces live» расширяется колонкой/строками «какие ADR стоят за этим»).
   WORKFLOW.md и docs/ — человеческие документы, теги там остаются.

3. **Канон процедуры — skills.** Процедуру исполняет агент, поэтому она живёт
   в feature-flow/incident-flow. WORKFLOW.md сжимается до обзора: две
   диаграммы, карта инструментов, grounding-таблица, статус-таблица, ссылки
   на skills. Дублирующие процедурные разделы (тиры, эпики, disputed tests,
   who-writes-tests) из WORKFLOW.md уходят — остаётся одна строка + ссылка.

4. **Языковая политика.**
   - Текст промптов (skills, agents, review-prompt, комментарии в конфигах
     кита) — **английский**. repo-auditor переводится на английский.
   - Вывод агента, адресованный человеку, — **русский**: вопросы разработчику
     (plan-griller: Q / Why it matters / Recommended answer), комментарии в
     YouTrack (intake-вопросы, handoff для QA), пояснения findings ревьюеров,
     stop-/done-отчёты executor и test-author.
   - Машиночитаемые форматы, теги и вердикты — английские: BLOCKING/ASSUMABLE,
     PLAN HOLDS / FIX THE PLAN, severity, `LGTM - no CRITICAL/HIGH issues`,
     строки формата вывода.
   - Доки (docs/, ADR, глоссарий) — русские; уже английские не переводим
     без отдельного решения.
   - **Исключение**: tools/cf/* остаются русскими — это внутренние
     миграционные протоколы conversation_flow, подлежат заморозке после
     фазы 3, полный перевод = реструктуризация, которая им не положена.

5. **Дубли reviewer-агентов — осознанные.** Файл сабагента обязан быть
   самодостаточным (Claude Code не умеет include), поэтому общие блоки
   остаются в обоих файлах, но каждый открывается маркером
   `<!-- shared block: edit in sync with <другой файл> -->`. Никакой сборки
   из фрагментов не заводим.

6. **Объём правок для кода-файлов** (Makefile.sdd, sdd-ci.yml, autoreview.yml,
   living-spec-check.sh, main-drift.sh): тексты (комментарии, echo, usage)
   плюс мелкая логика, если всплывёт при чтении, — с прогоном self-check/теста.
   tools/cf/*.md — только light pass (фактический дрейф, неясные строки).

7. **Верификация ревизии** — dry-run на реальном тикете с новыми текстами;
   репозиторий выбирается после ревизии. Ревью диффов делает Daniil;
   коммиты — его.

8. **Исполнение** — главная сессия как дирижёр, работа сабагентам
   (opus для канон-текстов и ревьюеров, sonnet для механики); перед рерайтом
   один research-сабагент собирает эталонный чеклист «как писать agent/skill
   тексты» из актуальных доков Anthropic. План волн — docs/PLAN_TEXTS.md.

## Последствия

- Каждое правило существует в одном исполняемом месте (skill/agent) и одном
  человеческом (WORKFLOW/ADR); связь — grounding-таблица.
- Промпты становятся короче и чище без потери трассируемости: `git blame` +
  grounding-таблица отвечают «откуда правило».
- Цена: при изменении правила нужно не забыть grounding-таблицу (советуемая
  проверка в grill-чеклист следующих ADR) и sync-дубли ревьюеров (маркер
  напоминает).
- repo-auditor меняет язык — его вывод (scorecard, находки) остаётся русским.
