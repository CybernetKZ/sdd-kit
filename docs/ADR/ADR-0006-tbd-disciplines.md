# ADR-0006. Trunk-Based Development: берём дисциплины, не отказываемся от PR

Статус: **принято** (решения подтверждены Daniil 2026-07-30 в grill-сессии). Дата: 2026-07-30.

## Решение

Схема веток не меняется: короткая ветка -> pull request -> dev.
Прямые коммиты в trunk не вводим.
Из Trunk-Based Development берём только дисциплины и превращаем их в машинные гейты:

1. **Гейт возраста ветки** в `sdd-ci.yml`.
   Считаем возраст merge-base ветки с dev.
   Старше 2 дней - предупреждение. Старше 5 дней - проверка красная.
   Исключение - лейбл `long-lived-ok` на PR.
2. **Гейт размера PR** в `sdd-ci.yml` (CodelyTV/pr-size-labeler или аналог).
   Пороги включаем сразу ("канон": XL примерно 1500 изменённых строк),
   но задаём их на репозиторий в `profiles/<repo>.env` - у WBN и cybernet3.0 разные профили PR.
   Исключение - лейбл `xl-ok`.
3. **Лейблы-исключения может вешать любой**, но CI требует секцию "Why XL" / "Why long-lived"
   в описании PR с обоснованием. Пустое обоснование - гейт красный.
4. **Локальное предупреждение** в pre-commit: ветка старше 2 дней - совет "rebase или дели OpenSpec change".
   Только предупреждение, не блок.
5. В skill `feature-flow` добавляется правило: ветка живёт не дольше 2 дней;
   если OpenSpec change больше - дели его на несколько change с независимой ценностью.

## Почему не "чистый trunk"

- Все наши гейты (sdd-gate, autoreview, spec-guard в CI) висят на pull request.
  Убрать PR - убрать точку принуждения. Принудимость - критерий с весом 25.
- Мы уже видели прямые коммиты в dev: cybernet3.0, 1780 коммитов, покрытие тикетами 12% (OUR_PATTERNS.md).
- Сам trunkbaseddevelopment.com рекомендует короткие ветки + PR, когда ревью обязательно.

## Настоящая проблема - размер батча

Медиана PR в WBN 412 строк, но p90 - 4221 строка и 62 файла.
Большие батчи прячут дефекты и создают очередь на ревью.
Отсюда важное следствие: блокирующая проверка перед PR обязана быть быстрой.
Блокирует только `make sdd-check`. AI-ревью остаётся советом, вторую блокирующую LLM-проверку не добавляем.

## Отклонённые варианты

- **Чистый trunk (прямые коммиты в dev)** - отклонено: гейты теряют точку крепления.
- **Спринт наблюдения перед включением порогов** - отклонено Daniil: пороги включаем сразу,
  клапан давления - лейблы-исключения с обоснованием.
- **Единые пороги на все репозитории** - отклонено: пороги задаются в профиле репозитория.

## Примечание 2026-07-31

Обнаружен баг bootstrap-скрипта кита (2026-07-31): профиль `profiles/<repo>.env` подбирается
по имени директории клона (basename), поэтому если клон называется не так, как репозиторий,
профиль не подхватывается автоматически - привязку нужно проставлять руками.
