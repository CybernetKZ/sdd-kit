## Паттерны

**nude** воспроизвёл ручной воркфлоу из INIT.md: человек диктует фазы
(PLAN -> implement -> review), opus дирижирует, 7 sonnet-субагентов копают и
пишут. Сам нашёл SSO-цепочку (user-context для API-ключей) и починил её -
самый широкий охват из всех прогонов задачи.

**sdd** после одного слэша `/feature-flow WEB-2314` прошёл почти автономно:
youtrack MCP (тикет+комменты+линки), openspec-цикл (new -> validate -> show,
десятки вызовов), `graphify query`, спека из store (external-webapi-
authorization) как контракт. Opus делегировал меньше (sonnet out 90k vs
164k) - методология вела его по шагам, и он больше делал сам в main-цикле.
Serena/headroom были подключены, но прямых вызовов их инструментов в
транскрипте нет - для этой задачи не понадобились.

**Ревью-финал sdd - сильнейший момент прогона**: панель из 3 агентов дала
BLOCK и поймала CRITICAL до сдачи - NameError в `main.py`, ронявший весь
gateway на старте при пустом `VOICE_AGENT_INTERNAL_API_KEY` (дефолт из
`.env.example` этого же диффа). Плюс HIGH: `x-total-count`/`x-page-count`
пролетали из firm-unaware апстрима мимо фильтра - срезаны на scoped-роутах.
Плюс два MEDIUM (upstream-401 наружу -> 502; непокрытая ветка 403). Агент
также сам поймал методологическую ошибку своей проверки ("сравнивал имена
упавших тестов, а не причины") и пересверил причины с baseline дословно.

**Глубина дизайна sdd**: firm-scoping как декларативный флаг правила
(`scope_to_firm`), fail-closed при неразрешимой фирме, гейтвей владеет
VAC-кредом (клиентский X-API-Key срезается безусловно), 404-неразличимость
скрытых чужих ресурсов, mini-report о VA-side дыре (per repo rule "не чини
чужое - запиши"). Nude такой глубины изоляции по фирме не строил.

## Честные оговорки

- n=1, интерактив: темп/качество зависят от человека за рулём; порядок
  nude->sdd (второй прогон выигрывает от свежей памяти оператора о задаче).
- sdd-арма получила youtrack MCP -> тикет из первоисточника; nude получил
  текст руками. Это свойство армы "kit+tools", а не ошибка.
- Судейства и кросс-ревью диффов не было; "оба task_success=1" -
  предварительно, по зелёным тестам и самооценке сессий.
- Пока не снято из-за перебоя классификатора (допишу позже): файл диффа sdd
  в архив, ruff-гейт sdd (внутри сессии `ruff --select F821` чист).

## Вывод m1 (осторожный)

На реальной мультифайловой фиче с интерактивным оператором sdd-kit+tools дал:
**−31% времени, −50% промптов человека, +17% стоимости**, более глубокий
дизайн безопасности, пойманный до сдачи CRITICAL и полный комплект
процессных/ops-артефактов. Цена - больше opus-токенов в main-цикле (спеки и
методология читаются дирижёром) и +$4.6 к сессии. Если время разработчика
дороже $9/час разницы - kit окупился уже в этом прогоне; статистики (n≥3,
другие типы задач) по-прежнему нет.
