# Ручной бенчмарк sdd-kit - инструкция

Роли: **ты ведёшь сессии Claude Code руками** (интерактивно, как в реальной
работе). **Кондуктор (Claude в этом чате) только фиксирует**: снимает
снапшоты до/после, собирает метрики из OTEL, диффы, гейты, транскрипты -
и складывает всё в `/home/octrow/cybernet/refactor_v4/logs/`.

Минимальный прогон: 1 сессия nude + 1 сессия sdd-kit, одна и та же задача,
последовательно (не параллельно!).

---

## 0. Перед началом (один раз)

Скажи кондуктору: **"подготовь ручной бенчмарк"**. Он делает (проверенная
последовательность, m1 2026-07-29):

1. **Свежие чистые клоны на фиксированном SHA.** Клонирует ЛОКАЛЬНО из рабочего
   репо (`git clone --local <src> <dest>`) и делает `checkout -B bench-base <SHA>`,
   чтобы получить чистое дерево коммита независимо от грязного рабочего репо.
   НЕ клонировать из другого bench-клона - он может нести правки прошлого прогона.
   Push отключается удалением remote (`git remote remove origin`). Оба клона -
   `refactor_v4/nude-claude/web-backend-new` и `.../sdd-kit-claude/web-backend-new` -
   на одном SHA (проверить `rev-parse`).
2. **Копирует реальные `.env` в ОБА клона** (8 сервисов WBN; в git их нет,
   в `.env.example` секретов нет). Нужны для pytest-гейта и для задач,
   зависящих от конфигурации. `.env` в `.gitignore` - в дифф/коммит не попадают.
3. **Ставит kit на arm B** (`sdd-kit/bootstrap.sh`), затем приводит arm B к
   РЕАЛИСТИЧНОМУ состоянию "репо, принявшего kit": заменяет шаблонный AGENTS.md
   (bootstrap кладёт заглушку с TODO) на курированный из рабочего репо и
   подсевает добытые repo-спеки (`openspec/specs/*`). Проверяет store
   `cybernet-specs`, `references:`, `make sdd-check` - и докладывает, что посеяно.
4. **Коммитит состояние arm B в `bench-base`** (kit-файлы + AGENTS.md + спеки),
   чтобы дифф задачи потом был чистым (только правки задачи, без обвеса).
   arm A остаётся голой (ни `.claude`, ни AGENTS.md) - коммитить нечего.
5. **OTEL-коллектор** (docker `bench-otel`, порт 4317) - поднимает/проверяет приём.
6. **Стартовый снапшот** в `/home/octrow/cybernet/refactor_v4/logs/prep-<sha>-snapshot.txt`: base SHA,
   версия claude CLI, версии инструментов, baseline гейтов (ruff на чистом клоне;
   pytest-baseline - при поднятом стеке).
7. Выдаёт два готовых export-блока (ниже).

Реши заранее и скажи кондуктору:
- **текст задачи** (вставишь сам в обе сессии, одинаковый; фиксируется в
  `~/bench/prompt-v2.md` + `clarify.md`);
- **модель**: одинаковая в обеих армах (по умолчанию `opus` main + sonnet-субагенты);
- **конфиг для nude**: чистый (`CLAUDE_CONFIG_DIR=~/bench/cfg-a`, без skills/hooks)
  или твой боевой `~/.claude` (это уже "арма C" - так и запишем).

## 1. Сессия 1 - nude

```bash
cd /home/octrow/cybernet/refactor_v4/nude-claude/web-backend-new

# чистый конфиг: НОЛЬ mcp/skills/plugins/hooks/CLAUDE.md (проверено кондуктором)
export CLAUDE_CONFIG_DIR=$HOME/bench/cfg-a

# телеметрия (тег арму!)
export CLAUDE_CODE_ENABLE_TELEMETRY=1 OTEL_METRICS_EXPORTER=otlp OTEL_LOGS_EXPORTER=otlp
export OTEL_EXPORTER_OTLP_PROTOCOL=grpc OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317
export OTEL_METRIC_EXPORT_INTERVAL=10000
export OTEL_RESOURCE_ATTRIBUTES="arm=nude,task=WEB-2314,run=m1"

# --strict-mcp-config: игнорировать ЛЮБЫЕ источники MCP (пояс и подтяжки)
claude --model opus --strict-mcp-config
```

Протокол внутри сессии:
1. Скажи кондуктору "**старт nude**" (он зафиксирует время и состояние).
2. Вставь текст задачи (одинаковый для обеих арм; без походов в YouTrack
   из сессии - текст даёшь сам).
3. Работай как обычно: уточняй, направляй, отклоняй правки. Каждое твоё
   сообщение и каждый reject фиксируются автоматически (транскрипт + OTEL).
4. Критерий финиша - одинаковый для обеих арм, реши до старта. Например:
   "код + тесты + ruff/pytest зелёные + ты бы открыл PR".
5. Выйди из claude (Ctrl+D) и скажи кондуктору "**стоп nude**".
   НЕ коммить и не откатывай ничего - снятие диффа делает кондуктор.

## 2. Сессия 2 - sdd-kit (после полного завершения сессии 1)

```bash
cd /home/octrow/cybernet/refactor_v4/sdd-kit-claude/web-backend-new

export CLAUDE_CONFIG_DIR=$HOME/bench/cfg-b   # тот же принцип, что в nude

export CLAUDE_CODE_ENABLE_TELEMETRY=1 OTEL_METRICS_EXPORTER=otlp OTEL_LOGS_EXPORTER=otlp
export OTEL_EXPORTER_OTLP_PROTOCOL=grpc OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317

```

Здесь MCP из `.mcp.json` (context7, youtrack) - часть kit'а: при вопросе о
доверии к project MCP серверам - одобри.

Протокол: "**старт sdd**" -> тот же текст задачи -> работай по kit-методологии
(feature-flow сам поведёт: openspec change -> имплементация -> тесты -> ревью)
-> "**стоп sdd**". Тот же критерий финиша.

## 3. Что фиксирует кондуктор (автоматически, по "старт/стоп")

| Когда | Что |
|---|---|
| старт | время, SHA, `claude --version`, чистота клона, конфиг армы |
| процесс | OTEL-поток пишется сам: токены по типам И ПО МОДЕЛЯМ, cost_usd, tool calls, compactions, api errors, skill_activated |
| стоп | wall clock; дифф от baseline; список файлов; число твоих промптов (human turns) и отклонённых правок; гейты (ruff - только новые нарушения, pytest - только новые падения); архив транскрипта |
| после обеих | сводная таблица nude vs sdd + по-модельная разбивка стоимости; всё в `/home/octrow/cybernet/refactor_v4/logs/`; отчёт на русском |

## 4. Правила честности (коротко)

- Одна задача, один текст, вставленный одинаково в обе армы.
- Сессии последовательно; во время сессии кондуктор не запускает ничего
  тяжёлого на машине.
- Модельный воркфлоу одинаковый в обеих армах и соответствует реальному:
  **opus как main brain** (планирование/дирижирование), **sonnet-субагенты
  на исполнение**; для особо сложных задач main = fable - но тогда в ОБЕИХ
  армах. Смена модели в процессе фиксируется (OTEL даёт по-модельную
  разбивку токенов и стоимости, "дешёвых подмен" не скроешь).
- Порядок арм чередуй между прогонами (m1: nude->sdd, m2: sdd->nude).
- Считай сам только одно: **сколько раз тебе пришлось вмешаться, чтобы
  вырулить агента** (переформулировки, отмены, "не туда") - субъективное
  число, назови его кондуктору на "стоп", он запишет рядом с автоматикой.
- Не смотри на метрики первой армы до завершения второй.

## 5. Быстрые команды кондуктору

| Фраза | Действие |
|---|---|
| "подготовь ручной бенчмарк" | шаг 0 полностью |
| "старт nude" / "старт sdd" | стартовый снапшот армы |
| "стоп nude" / "стоп sdd" | снятие диффа, метрик, гейтов, архив |
| "отчёт" | сводная таблица + выводы + логи |
| "сбрось арму X" | вернуть клон к `bench-base` (`git checkout bench-base && git clean -fdq`; `.env` игнорируются и переживают сброс) |
| "пересобери с нуля" | удалить оба клона и заново пройти шаг 0 (свежие клоны на том же SHA) |
