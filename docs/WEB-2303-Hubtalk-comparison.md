# Hubtalk ai platform comparison 

# HubTalk AI — Анализ пробелов при миграции: Сайт 1 → Сайт 2

> **Сайт 1** — текущий production.
>
> **Сайт 2** — целевая платформа.

---

# 1. Обзор и контекст миграции

## Цель документа

Документ описывает функциональные различия между текущей платформой HubTalk AI (**Сайт 1**) и новой платформой (**Сайт 2**) с целью определить функции, которые необходимо перенести до полного перехода на новую архитектуру.

Сравнение включает:

- пользовательский интерфейс;
- информационную архитектуру;
- функциональный паритет;
- административные возможности;
- аналитику;
- инфраструктуру;
- AI-конфигурацию;
- базы знаний;
- план миграции.

---

## Контекст

**Сайт 1** — текущая production-платформа.

**Сайт 2** — новая версия платформы, архитектура которой значительно мощнее благодаря появлению:

- визуального конструктора сценариев;
- системы публикации;
- версионирования;
- Components;
- MCP;
- мониторинга инфраструктуры;
- современной организации сущностей.

При этом часть возможностей Сайта 1 пока отсутствует и требует миграции.

---

## Статусы в документе

| Статус | Значение |
|---------|----------|
| **Только Сайт 1** | Функция отсутствует в Сайте 2. Требуется реализовать. |
| **Только Сайт 2** | Уже реализовано. Перенос не требуется. |
| **Сопоставимо** | Функция присутствует в обеих системах. Требуется проверить полноту паритета. |

# 2. Дизайн и визуальная система

| Аспект | Сайт 1 | Сайт 2 |
|--------|--------|--------|
| **Тема** | Светлая по умолчанию (есть переключатель тёмной темы) | Тёмная по умолчанию (есть переключатель темы) |
| **Акцентные цвета** | Фиолетовый / синий. В графиках используются красный, оранжевый и синий | Основной цвет — синий/индиго. Статусы отображаются зелёными и жёлтыми бейджами |
| **Компоновка** | Боковое меню + breadcrumb. Разделы меню раскрываются (Dashboards, Conversations, Administration и др.) | Боковое меню + breadcrumb. Меню одноуровневое без раскрывающихся разделов |
| **Плотность интерфейса** | Плотный административный интерфейс с большим количеством таблиц | Современный карточный интерфейс с увеличенными отступами |
| **Визуализация данных** | Donut Chart, Bar Chart, Area Chart, Line Chart, Heatmap, Progress Ring | Минимум графиков. Основной акцент сделан на KPI-карточках и статусах |
| **Отличительный элемент** | Progress Ring и тепловая карта звонков | Визуальный Flow Builder с Mini Map и статусами публикации |
| **Консистентность UI** | Единый шаблон всех административных страниц: Filters → View → Primary Action → Table → Context Menu | Единый стиль карточек агентов и справочников Models / Voices / ASR |

## Вывод

### Сайт 1

**Преимущества**

- развитые административные экраны;
- насыщенные операционные дашборды;
- большое количество аналитики;
- зрелые CRUD-интерфейсы.

**Недостатки**

- высокая плотность интерфейса;
- устаревший внешний вид;
- отсутствие визуального проектирования сценариев.

---

### Сайт 2

**Преимущества**

- современный UX;
- визуальный конструктор сценариев;
- версионирование;
- публикация изменений;
- Components;
- Copilot;
- MCP;
- лучшая организация сущностей.

**Недостатки**

- менее информативный Dashboard;
- отсутствует часть операционной аналитики;
- некоторые административные функции ещё не перенесены.

---

## Рекомендация

Сохранять текущий дизайн Сайта 2.

При миграции необходимо вернуть функциональность операционной аналитики Сайта 1:

- Dashboard;
- Campaign Analytics;
- KPI;
- Heatmap;
- отчётность.

Без изменения современной архитектуры интерфейса Сайта 2.




# 3. Информационная архитектура

## Сравнение структуры навигации

| Навигация Сайта 1 | Навигация Сайта 2 |
|-------------------|-------------------|
| **Dashboards** → Operations Dashboard, Campaign Goal Tracking | **Dashboard** (единая сводка по агентам и сессиям) |
| **Campaigns** | **Agents** (карточки агентов, версии, публикация) |
| **Conversations** → Outbound, Inbound, Chats | **Telephony** (SIP Trunks) |
| **Agents** | **History** (единая история звонков и чатов) |
| **Knowledge Base** | **Incidents** |
| **Detailed Report** → Outbound, Inbound | **API Keys** |
| **Administration** → Users, Companies, Servers, Countries, Languages, SIP Trunks, Agent Languages, LLM Providers, LLMs, Segments, Segment Templates, TTS Providers, TTS, ASR Providers, ASR, WebAPI/API Keys | **Models**, **Voices**, **ASR Models**, **Realtime Models**, **Realtime Voices** |
| — | **MCP Servers** |
| — | **Components** |
| — | **Knowledge Bases** |
| — | **System Health** |
| — | **Organization** |
| — | **Settings** |

---

## Основные отличия

### Сайт 1

Навигация построена вокруг бизнес-процессов:

- Dashboards
- Campaigns
- Conversations
- Reports
- Administration

Практически вся системная конфигурация находится внутри большого раздела **Administration**.

Такой подход характерен для классических административных систем.

---

### Сайт 2

Навигация построена вокруг жизненного цикла AI-агента.

Основные этапы:

```
Создание агента
        ↓
Настройка Flow
        ↓
Публикация
        ↓
Мониторинг
        ↓
История
```

Инфраструктурные сущности вынесены в отдельные разделы:

- Models
- Voices
- ASR
- MCP
- Components
- System Health

---

## Что изменилось

| Изменение | Комментарий |
|------------|-------------|
| Administration перестал быть "универсальным разделом" | Конфигурация распределена по предметным областям |
| Добавились Components | Повторное использование частей сценариев |
| Добавились MCP Servers | Подключение внешних инструментов |
| Добавился System Health | Мониторинг инфраструктуры |
| Появились отдельные справочники моделей | Models, Voices, ASR, Realtime Models |
| History объединила Outbound, Inbound и Chats | История стала единой страницей с фильтрами |
| Dashboard стал проще | Часть аналитики отсутствует |

---

## Плюсы новой архитектуры

- лучше масштабируется;
- проще ориентироваться разработчикам;
- инфраструктура отделена от бизнес-функций;
- меньше вложенности меню;
- логика соответствует процессу разработки AI-агента.

---

## Недостающие элементы

Несмотря на более современную архитектуру, в Сайте 2 пока отсутствуют некоторые важные разделы:

- Campaigns;
- Campaign Goal Tracking;
- Detailed Report;
- Countries;
- Languages;
- Servers;
- Segment Templates.

---

## Итог

Архитектура Сайта 2 значительно современнее и лучше соответствует платформе для разработки AI-агентов.

При этом для полного перехода необходимо перенести часть бизнес-функциональности Сайта 1, особенно связанную с:

- операционной аналитикой;
- управлением кампаниями;
- справочниками;
- отчётностью;
- сегментами анализа звонков.


# 4. Чек-лист пробелов при миграции (Сайт 1 → Сайт 2)

> **Только Сайт 1** = реализовать в Сайте 2.
>
> **Только Сайт 2** = уже есть.
>
> **Сопоставимо** = проверить паритет.

| Функция | Сайт 1 (текущий) | Сайт 2 (целевой) | Статус миграции |
|---------|------------------|------------------|-----------------|
| **Операционный дашборд в реальном времени** | Да — насыщенный (тональность, % сдерживания, тепловая карта, распределение длительности звонков) | Частично — Dashboard представляет собой простую сводку по агентам/сессиям | Сайт 1 выигрывает по операционной наглядности |
| **Управление кампаниями** | Да — полный список кампаний + отслеживание целей по сегментам с KPI | Аналога нет | Только Сайт 1 |
| **История диалогов** | Разделена по страницам Outbound / Inbound / Chats | Единая история History с расширенными фильтрами (результат, тональность, диспозиция, инциденты, серьёзность, статус проверки) | Фильтрация Сайта 2 более продвинута; фильтрация Сайта 1 проще, но разделена по каналам |
| **Конфигурация агента** | Простая форма: выпадающие списки язык/LLM/TTS/ASR + сворачиваемые разделы (Functions, Variables, Post Call Analysis, VAD, настройки звонка/речи/вебхуков, KB) | Полноценный визуальный узловой конструктор потока (Conversation, Function, Code, Logic Split, Extract Variables, Transfer, Component, MCP Tool, End) с публикацией/черновиками/версионированием, Copilot, импортом/экспортом, тестированием | Сайт 2 значительно мощнее для проектирования логики диалога |
| **Версионирование / публикация** | Не обнаружено | Да — Published vX, Unpublished changes, Discard changes, история версий агента | Только Сайт 2 |
| **Переиспользуемые компоненты** | Не обнаружено | Да — библиотечные (общие) и локальные компоненты агента с гибкостью/версионированием | Только Сайт 2 |
| **ИИ-ассистент для конструирования** | Не обнаружено | Да — «+ Copilot» в редакторе потока | Только Сайт 2 |
| **База знаний** | Да — список + прикрепление файлов (на уровне KB), простой статус | Да — список + модальное управление файлами, drag-and-drop, более широкий набор форматов (pdf/docx/pptx/xlsx и т.д.), прикрепление на уровне KB или отдельного узла диалога | Сайт 2 несколько гибче (прикрепление KB на уровне узла) |
| **Телефония / SIP** | Настраивается через Administration → SIP Trunks (префикс, входящие/исходящие номера, привязанные агенты) | Отдельная страница Telephony (транк, входящий, исходящий + привязанные агенты, адрес/протокол SBC) | Сопоставимо; Сайт 2 выносит это в верхний уровень навигации |
| **Инциденты / проблемы, выявленные ИИ** | Не обнаружено | Да — отдельная страница Incidents (серьёзность, статус, по агенту) | Только Сайт 2 |
| **Мониторинг здоровья системы / инфраструктуры** | Не обнаружено | Да — активные звонки, глубина/задержка очередей/DLQ, здоровье компонентов (db/redis/minio/livekit), задержка внешних провайдеров (deepgram/elevenlabs/openai и т.д.) | Только Сайт 2 — существенное отличие |



| Функция | Сайт 1 (текущий) | Сайт 2 (целевой) | Статус миграции |
|---------|------------------|------------------|-----------------|
| **Справочник LLM** | Administration → LLMs — пользовательское имя, модель, endpoint, провайдер, переключатели ролей Main Prompt/Post-Call Analysis по модели | Models — более насыщенный справочник с актуальными ценами (за 1M токенов), ролями, живой проверкой соединения «Check», фильтром по провайдеру | Справочник Сайта 2 более актуален и детализирован; переключатель ролей по модели у Сайта 1 проще, но сопоставим |
| **Общесистемные роли LLM по умолчанию** | Не обнаружено как единый экран (переключатели ролей заданы по каждой модели отдельно) | Да — Settings → Models (LLM) — модели Execution / Classifier / Copilot (reasoning) / Simulation / Analytics (mass и deep tier), указан путь конфигурации (/app/config.docker.yaml) | Только Сайт 2 — централизует то, что у Сайта 1 распределено по переключателям отдельных моделей |

| **Справочник ASR** | Administration → ASR / ASR Providers | ASR models — та же идея, фильтр по провайдеру, флаги возможностей | Сопоставимо |

| **Управление кешем TTS** | Не обнаружено | Да — модальное окно очистки кеша TTS по агенту (по голосу / по опубликованной версии / весь workspace) + denylist для фраз | Только Сайт 2 — функция контроля операционных затрат |
| **Доступ к API** | Administration → WebAPI/API Keys — список ключей, отзыв | API keys — то же самое плюс встроенная документация (endpoints, Bearer-аутентификация, idempotency key, ссылки на /docs и openapi.json) | Сайт 2 документирует API прямо в продукте; Сайт 1 только управляет ключами |
| **Управление пользователями / ролями** | Administration → Users — имя/фамилия, телефон, компания, страна, язык, переключатели активен/подтверждён | Organization → Users — имя/email, организация, выпадающий список роли, статус входа; поддержка нескольких организаций | Сайт 2 тяготеет к мультитенантной/организационной модели; Сайт 1 — к однотенантной модели с более богатыми полями локали пользователя |
| **Компании / мультитенантность** | Administration → Companies — полный CRUD, юридический адрес, страна/язык | Organization — дерево организации с типом/брендом; показана одна организация «HubTalk AI» | Сайт 1 показывает более зрелые данные по нескольким компаниям; Сайт 2 предполагает мультиорганизационность, но менее заполнен данными |
| **Записи серверов / инфраструктуры** | Administration → Servers — имя, адрес, статус, ёмкость | Не обнаружено как отдельная страница (инфраструктура отражена через System Health) | Разный подход: Сайт 1 рассматривает серверы как инвентарь; Сайт 2 — как метрики здоровья в реальном времени |
| **Справочники Countries / Languages** | Да — полноценные CRUD-страницы администрирования | Не обнаружено как отдельные страницы | Только Сайт 1, в виде явных админ-таблиц |
| **Настройки внешнего вида / рабочего пространства** | Не обнаружено как единая страница настроек | Да — Settings: язык интерфейса, цветовая тема, значения по умолчанию для новых агентов, общесистемные роли моделей | Только Сайт 2 |




# 5. Уже реализовано в Сайте 2 (действий по миграции не требуется)

**Уже покрыто в Сайте 2, переноса не требуется.**

1. **Конфигурация агента** — визуальный конструктор потоков Сайта 2 (узлы **Conversation**, **Function**, **Code**, **Logic Split**, **Transfer**, **MCP Tool**, **Component**, **End**) полностью заменяет форму агента на выпадающих списках Сайта 1.

2. **База знаний** — версия Сайта 2 является надмножеством функционала (drag-and-drop, больше форматов файлов, прикрепление на уровне узла).

3. **Телефония / SIP** — присутствует в Сайте 2 как отдельная страница верхнего уровня, функционально эквивалентная таблице **SIP Trunks** в администрировании Сайта 1.

4. **Справочники LLM / голосов / ASR** — страницы **Models**, **Voices** и **ASR models** Сайта 2 более актуальны (живые цены, живая проверка соединения, флаги возможностей) и покрывают ту же область, что и административные страницы **LLM / TTS / ASR Providers** Сайта 1.

5. **Управление API-ключами** — страница **API Keys** Сайта 2 выполняет ту же функцию, что и **WebAPI / API Keys** Сайта 1, дополнительно предоставляя встроенную документацию.

6. **Пользователи** — **Organization → Users** в Сайте 2 покрывает ту же функцию, что и **Administration → Users** в Сайте 1 (на основе ролей, с поддержкой мультиорганизаций).




# 6. Необходимо перенести: функции, отсутствующие в Сайте 2

Отсутствует в Сайте 2, требуется перенести.

---

## Высокий приоритет — ключевые операционные функции

### 1. Аналитика операционного дашборда

Перенести следующие метрики:

- тональность звонков;
- коэффициент сдерживания;
- коэффициент дозвона;
- тепловая карта по часам;
- распределение длительности звонков.

**Статус:** в Сайте 2 отсутствует.

---

### 2. Управление кампаниями

Перенести:

- список кампаний;
- создание кампаний;
- отмену кампаний;
- отображение прогресса;
- Campaign Goal Tracking;
- KPI по сегментам:
  - Settlement;
  - Welcome;
  - NSF;
  - Termination.

**Статус:** в Сайте 2 отсутствует.

---

### 3. Segments + Segment Templates

Перенести самостоятельную систему:

- типизированные поля извлечения данных;
- Boolean;
- Number;
- Selector;
- списки вариантов;
- копирование между сегментами;
- перемещение между сегментами.

В Сайте 2 присутствует только встроенный раздел **Post Call Analysis**, который не является переиспользуемой схемой.

---

## Средний приоритет — административные / справочные данные

### 1. Countries

Перенести CRUD-страницу администрирования Countries.

**Статус:** в Сайте 2 отдельной страницы нет.

---

### 2. Languages

Перенести CRUD-страницу администрирования Languages.

**Статус:** в Сайте 2 отдельной страницы нет.

---

### 3. Servers

Перенести страницу администрирования Servers:

- имя;
- адрес;
- статус;
- ёмкость.

В Сайте 2 отображается только текущее состояние инфраструктуры (**System Health**), без отдельной CRUD-таблицы серверов.

---

### 4. Companies

Проверить перенос модели Companies.

Необходимо подтвердить, что объединённая история полностью покрывает функциональность отдельных разделов.



# 7. План миграции

## Последовательность действий

1. Перенести метрики операционного дашборда:
   - тональность;
   - сдерживание;
   - тепловая карта;
   - распределение длительности звонков.

   Разместить их в **Dashboard** Сайта 2 или в новой странице **Analytics**.

2. Перенести управление кампаниями и **Campaign Goal Tracking** как новый раздел верхнего уровня в Сайте 2.

3. Перенести **Segments** и **Segment Templates** как самостоятельную, переиспользуемую систему схем в Сайте 2 (а не оставлять конфигурацию пост-анализа звонка только встроенной в агента).

4. Добавить недостающие страницы справочных данных администрирования:
   - Countries;
   - Languages;
   - Servers.

   Либо подтвердить, что эквивалентное управление возможно через **Settings** / **Organization**.

5. Убедиться, что данные **Companies** (мультитенантность) полностью переносятся в модель **Organization** Сайта 2 без потери следующих полей:
   - юридический адрес;
   - страна;
   - язык.

6. Подтвердить, что:
   - экспорты **Detailed Report**;
   - раздельные представления **Outbound** / **Inbound** / **Chats**

   либо полностью воспроизведены в Сайте 2, либо их отсутствие обосновано использованием единой страницы **History** с фильтрами.

7. Только после завершения пунктов 1–6:
   - заморозить Сайт 1;
   - запустить Сайт 1 и Сайт 2 параллельно на период проверки;
   - после успешной валидации вывести Сайт 1 из эксплуатации.

## Примечание

До выполнения пунктов **1–3** Сайт 1 остаётся системой учёта для:

- отчётности;
- управления кампаниями.
