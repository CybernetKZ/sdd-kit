# verify-section — верификация capability-спеки против кода

Инструкция для агента-верификатора (отдельный агент, НЕ автор спеки —
ADR-0019 п.3: полная верификация по протоколу store).

## Вход

- `conversation_flow/openspec/specs/<capability>/spec.md` (свежесмайненная)
- Исходный раздел `docs/DOCUMENTATION.md` (для сверки полноты)

## Процесс

По каждому `### Requirement:`:
1. Открыть каждый `enforced:`-якорь, прочитать код. Requirement подтверждён
   только если поведение видно в коде (не по памяти, не по докам).
2. Каждый Scenario мысленно прогнать против кода: WHEN достижим? THEN
   действительно наступает? Есть ли тест (grep по tests/)?
3. Вердикт по Requirement: CONFIRMED / MISMATCH (код ведёт себя иначе —
   указать файл:строку и чем) / UNVERIFIABLE (кода не нашёл).
4. Полнота: нормативные утверждения исходного §, не попавшие в спеку, —
   в список MISSING.

Ничего не править ни в коде, ни в спеке, КРОМЕ: явные опечатки якорей
(файл переименован и т.п.) можно исправить в спеке, пометив в отчёте.

## Отчёт агента

Terse-таблица: requirement id → вердикт (+файл:строка для MISMATCH).
Отдельно: MISSING-список, кандидаты в `docs/DEFECTS_CF.md` (MISMATCH = дефект
кода или спеки — не решать, просто зафиксировать), покрытие тестами
(id → test-файл или «нет теста»).
