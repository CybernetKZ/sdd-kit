# sdd-kit

Инструмент для быстрой настройки (bootstrap) разработки на основе спецификаций (SDD) в любом репозитории — как новом,
так и старом.
Всего один скрипт. Он идемпотентен: никогда не перезаписывает существующие файлы, а только добавляет то, чего не
хватает.

## Использование

```bash
sdd-kit/bootstrap.sh /path/to/repo   # для каждого репозитория: ставит нужные файлы SDD, хуки и проверки
sdd-kit/setup-dev.sh                 # для компьютера разработчика: ставит рекомендуемые личные инструменты
```

Запускать скрипт повторно — безопасно. Если запускать без интерактивного терминала (без TTY), вопросы скрипта
пропускаются и вместо них выводятся инструкции. Флаг `SDD_KIT_ASSUME_YES=1` автоматически подтверждает установку (кроме
токена YouTrack — его всегда нужно вводить вручную).

## Что устанавливает скрипт

| Файл / Артефакт                            | Зачем нужен                                                                                                                                                                                                                                                                                 |
|--------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `AGENTS.md` (и симлинк `CLAUDE.md`)        | Главный контекст для ИИ-агентов, до 500 строк. Старый файл `CLAUDE.md` просто переименовывается, ничего не удаляется.                                                                                                                                                                       |
| `openspec/`                                | Папка инициализации OpenSpec. Здесь живут спецификации и история изменений.                                                                                                                                                                                                                 |
| `Makefile.sdd` (и `-include` в Makefile)   | Команда `make sdd-check`: проверяет, что `AGENTS.md` существует и <500 строк + валидирует спецификации + запускает линтер спецификаций и проверку фича-флагов. При любой ошибке выдает четкую команду `next:` (что делать дальше).                                                          |
| `templates/feature_flags.py`               | Реестр фича-флагов с указанием владельца, тикета и срока жизни. Команда `make sdd-flags` предупреждает за 7 дней до протухания флага, а потом роняет CI.                                                                                                                                    |
| `.github/workflows/sdd-ci.yml`             | Обязательная SDD-проверка для каждого Pull Request (PR). Плюс проверка `tbd-gates`: следит за возрастом ветки (падает, если старше 5 дней) и размером PR (падает, если >1500 строк). Чтобы обойти лимиты метками `long-lived-ok`/`xl-ok`, нужно обязательно написать причину в описании PR. |
| `.github/workflows/autoreview.yml`         | Автоматическое код-ревью для PR: сначала статические анализаторы (ruff, radon, semgrep и др.) через reviewdog оставляют комментарии к коду, затем ИИ-ревьювер (Claude) проверяет этот отчет перед публикацией.                                                                              |
| `.claude/agents/*-reviewer.md`             | Инструкции (промпты) для ИИ-ревьюверов по Python, базам данных, FastAPI и общему коду.                                                                                                                                                                                                      |
| `.claude/hooks/` + `.claude/settings.json` | Блокировщик `spec-guard` (запрещает менять код, если нет активной спецификации изменения), запрет на коммиты с `--no-verify` и сохранение сессии ИИ (чтобы агенты не теряли контекст при перезапуске).                                                                                      |
| `.claude/scripts/spec-lint.py`             | Линтер спецификаций: проверяет их актуальность. Работает внутри `sdd-check`. Пока не включен `SPEC_LINT_STRICT=1`, выдает только предупреждения.                                                                                                                                            |
| `.git/hooks/pre-commit`                    | Защита от случайных коммитов в главные ветки (main/master/prod), автоформатирование Python-кода (ruff), базовые проверки гигиены (маркеры слияния git, файлы >5 МБ, забытые `breakpoint()`, токены/секреты в коде, сломанный JSON/YAML) и запуск `make sdd-check`.                          |
| `.claude/scripts/repo-audit.sh`            | Аудит чистоты: ищет мусор вроде лишних MCP-серверов или чужих конфигов. Запускается в конце установки и через `make sdd-audit`. Выдает точную команду для исправления ошибки.                                                                                                               |
| `.claude/scripts/sdd-doctor.sh`            | Диагностика рабочего окружения (`make sdd-doctor`): проверяет наличие нужных утилит (git, node, python, ruff и др.), авторизацию, хуки и наличие нужных файликов `.env` (проверяет только их наличие, а не сами секреты!).                                                                  |
| `.mcp.json`                                | Подключение MCP-серверов к проекту: context7 и youtrack. Для фронтенда добавляет chrome-devtools.                                                                                                                                                                                           |
| `.claude/skills/feature-flow/`             | Рабочий процесс "от тикета до PR" в виде инструкции для ИИ: изучение тикета → создание спеки → **QA пишет тесты ДО написания кода (разработчики тесты не пишут)** → написание кода → ревью → PR.                                                                                            |
| `.claude/skills/incident-flow/`            | Инструкция для ИИ по работе с инцидентами: сбор улик → документ с корневой причиной → спека изменения → сначала написание регресс-теста, потом исправление бага.                                                                                                                            |
| `ruff.toml`                                | Конфиг линтера Ruff. Устанавливается, ТОЛЬКО если в репозитории нет своего конфига.                                                                                                                                                                                                         |
| `.spec-guard-paths`                        | Настройка для известных репозиториев (см. "Профили"), чтобы блокировать изменение только рабочего кода (тесты и доки менять можно всегда).                                                                                                                                                  |

## Профили

Скрипт умеет подстраиваться под известные репозитории с помощью файлов `profiles/<имя-репо>.env`. Если имя папки
совпадает с профилем, скрипт дополнительно:

- Настраивает пути для `spec-guard` (чтобы он следил только за продакшен-кодом);
- Подключает центральное хранилище спецификаций (store): при необходимости клонирует его, регистрирует и добавляет
  нужные ссылки.
- Не ставит Python-инструменты, если проект не на Python (`PROFILE_SKIP_PY=1`).
- Подсказывает скрипту `sdd-doctor`, какие `.env` файлы должны быть у разработчика для успешного запуска проекта.

*Встроенные профили:* web-backend-new, voice-agent-constructor-backend, cybernet3.0, web-frontend-new и др. Для
неизвестных репозиториев применяется стандартная установка.

## Зависимости

При запуске проверяется наличие: `git`, `node/npx`, `uv`.
Если не хватает `openspec` или `youtrack-mcp`, скрипт предложит их установить. Если нет токена YouTrack, скрипт даст
ссылку, где его взять, безопасно считает его и положит *только* в локальный `.env` (в репозиторий токен никогда не
попадет).

## Что нужно сделать руками после установки

1. Заполнить TODO (пропуски) в файле `AGENTS.md`.
2. Создать файл `.spec-guard-paths` (список папок с важным кодом, по одному на строку). *Для известных проектов делается
   автоматически.*
3. Начать создавать спецификации через агента `spec-miner`.
4. В GitHub: сделать проверку `sdd-gate` обязательной для слияния PR, включить защиту основной ветки.
5. Авторизация для ИИ-ревью (только подписка, без API-ключей): токены привязываются к конкретному разработчику и
   компьютеру, не нужно добавлять общие секреты в GitHub. Для проверки ревью локально используйте `make sdd-review`.

## Инструменты разработчика: setup-dev.sh

Скрипт `bootstrap.sh` настраивает сам репозиторий. Но личные инструменты разработчика нужно ставить отдельно на каждый
компьютер, чтобы не засорять репозитории.
Запустите это один раз на своей машине:

```bash
sdd-kit/setup-dev.sh             # установит базовый набор (рекомендуется)
sdd-kit/setup-dev.sh --minimal   # старое поведение: спрашивает про каждый инструмент
```

**Базовый набор (улучшает код, экономит деньги на API):**

* `ponytail` — заставляет ИИ писать минималистичный и рабочий код.
* `rtk` — сжимает вывод терминала для ИИ.
* `Graphify` — строит граф знаний по коду (ускоряет и удешевляет анализ).
* `Headroom` — сжимает контекст, экономя место в памяти ИИ.
* `ast-grep` — инструмент для массового рефакторинга кода.

*(Опционально можно поставить CLI-утилиты для интеграции с GitHub и браузером).*

## Настройки (переменные окружения)

* `YOUTRACK_URL` — адрес вашего YouTrack.
* `SDD_KIT_ASSUME_YES=1` — отвечать "Да" на все вопросы при установке (кроме токена).
* `SPEC_LINT_STRICT=1` — сделать ошибки линтера спецификаций блокирующими (CI будет падать).
* `SDD_AUDIT_STRICT=1` — сделать предупреждения аудита репозитория блокирующими.
* `SDD_ALLOW_PROTECTED=1` — разовый обход запрета на коммиты в защищенные ветки.

## Документация по процессам

* `WORKFLOW.md` — описание полного цикла работы команды: от появления задачи до влитого PR.
* `QA-SDD-PROCESS.md` — рабочий процесс QA: **тестировщики пишут тесты ДО реализации фичи** на основе спецификации.
  Разработчики не пишут тесты.

## Архитектурные принципы

Вывод всех скриптов и проверок сделан так, чтобы его легко читали ИИ-агенты: сначала идет главная мысль, явно пишется "0
проблем" (вместо пустоты), а при любой ошибке всегда дается конкретная команда `next:` (что делать для исправления).

Никакой магии: инструкции и "скиллы" для ИИ носят рекомендательный характер, ИИ может их проигнорировать. А вот хуки (
hooks) — это жесткий код, их проигнорировать нельзя. Поэтому все строгие запреты реализованы только в хуках и
CI-проверках.

## Структура папок

* `bootstrap.sh` — установщик для репозитория.
* `setup-dev.sh` — установщик для машины разработчика (личные утилиты).
* `profiles/` — настройки под конкретные репозитории.
* `templates/` — все файлы, которые копируются в ваш репозиторий при установке.
