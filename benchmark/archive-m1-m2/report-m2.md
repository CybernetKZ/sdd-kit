# Отчёт m2 — WEB-2234 (ручной бенчмарк, 2026-07-30)

Задача: **WEB-2234 «API upload xlsx сравнивает ненормализованные номера»** —
компактный багфикс: при загрузке файла обзвона дедупликация (CHECK / DELETE /
MERGE) сравнивает сырые строки, а внешний API — канонизированные MSISDN;
`+7 (702) 296-82-75` и `77022968275` должны схлопываться в одну группу.

(пин `mcp<2`, core-тулзы) на арме B, порядок **sdd → nude** (чередование с m1).

## Сравнение решений

Впервые обе армы дали **сопоставимые архитектуры** (в m1 были несовместимы):
обе нормализуют колонку телефона тем же `normalize_phone_number`, что и
внешний API (`NormalizedPhoneNumber`), прямо перед дедупликацией.

Отличия:
- **sdd — fail-fast**: `map(normalize_phone_number)` на всю колонку;
  невалидный номер роняет загрузку уже на шаге нормализации — точка ошибки
  сдвинулась раньше прежней (поведенческое изменение для невалидных значений).
- **nude — консервативнее**: нормализует только уникальные значения
  (экономия на повторном парсинге `phonenumbers`), невалидные оставляет
  сырыми, чтобы ValueError поднялся **в прежней точке** (`_process_chunk`)
  с прежней семантикой; магический индекс вынесен в константу
  `PHONE_COLUMN_INDEX` (config.py).
- Ревью-панель sdd поймала до сдачи ошибки имплементации (тесты дошли до
  9 passed), но **семантический сдвиг точки ошибки не пометила**; nude-ревью
  прицельно сверялось с исходной целью и удержало прежнюю семантику.

## m1 ↔ m2: эффект размера задачи

| | m1 (WEB-2314, фича на 2 сервиса) | m2 (WEB-2234, точечный багфикс) |
|---|---|---|
| Время | sdd **быстрее** на 31% | sdd **медленнее** на 45% |
| Деньги | sdd дороже на 17% | sdd дороже на 57% |
| Промпты | 2 vs 4 | 3 vs 4 |
| Архитектуры | несовместимы | совпадают по сути |

Вывод: у kit'а есть **примерно фиксированный оверхед** (~$4–5 и ~15–20 мин:
интейк через youtrack, openspec-комплект, ревью-панель). На крупной/размытой
задаче (m1) он окупается — меньше вмешательств, методология страхует от
провала скоупа, артефакты (спеки, design, тест-кейсы) остаются команде. На
компактном багфиксе (m2) оверхед доминирует: nude быстрее, дешевле и в этот
раз ещё и семантически аккуратнее. Практический паттерн: **feature-flow — для
фич и размытых тикетов; для точечных багфиксов — лёгкий режим** (см. идею
«bugfix-flow lite» в открытых вопросах).

## Честность / отклонения m2

1. Метрики sdd-армы были показаны Daniil'у до старта nude (якорь-эффект).
2. Воркфлоу разошёлся: nude — только opus; sdd — opus + sonnet-субагенты.
   Стоимость nude при этом НЕ занижена (sonnet дешевле opus).
3. `lastModelUsage` в cfg-b не флашнулся — цифры sdd взяты из OTEL
   (10-сек интервал, теги армы; надёжно).
4. Ruff-«новые» в новых тест-файлах (SLF001) — известный bias гейта к новым
   файлам, в prod-коде обе армы чисты.
5. n=1 на задачу; итого выборка m1+m2 = 2 задачи × 2 армы.
